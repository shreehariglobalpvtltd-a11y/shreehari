# SHARI NAV ai1 — Google Maps / Apple Maps patterns vs SHARI NAV, gap checklist — 21 Oct 2026

Section 1 of the owner's master prompt asks for a reverse-engineering of Google Maps and Apple Maps
before the ai1 build. No REA (app-capture) MCP is connected in this session, so this is a written
reference instead of a live capture: the Google / Apple columns describe the 2025–26 phone apps as
generally known, not a recording. The SHARI NAV column is read from `navigate.html` at commit
`1d57804` (live `release-20261021-nv4` 1226261 + the ai1 hook infra); every number in it was checked
against the source on 21 Oct. The "ai1 adds" column is what the ai1 modules (KB, AI, TEMPLES, BORDER +
COST, SHGROUTE) add per the build spec of the same date, with its §9 amendments (A1–A19) and §10 product
amendments (P1–P25) applied. "Out" says what deliberately stays out and why. No code in this file.

Legend in the SHARI NAV column: **✔** present · **◐** partial · **✖** not there.

## 3. Sensors and gestures

| Pattern | Google / Apple | SHARI NAV today (nv4) | ai1 adds | Out — why |
|---|---|---|---|---|
| GPS `watchPosition` config | Native fused location | ✔ `enableHighAccuracy: true, maximumAge: 1500, timeout: 25000`; already-granted permission → blue dot at once; denied → one toast | AI asks to allow location before "nearest …" (action "Allow" → `startGeo()`); privacy: position rounded to 2 dp (≈ 1 km) on the phone and again in `nav-ai.php`, sent only for intents that need it (nearest / how to go / emergency / ETA / weather), route only for route questions, never the trip log (P10) | — |
| Smoothing | Fused, road-snapped | ✔ Kalman: predict by speed + heading, blend by reported accuracy, a jump > 250 m (or 4 × accuracy) restarts it, the motion sensor's "phone is lying still" damps wander; snapped to the route line within accuracy + 25 m | — | — |
| Dead-reckoning interpolation | Smooth 60 fps puck | ✔ `navFrame` eases the puck between fixes (250–1600 ms), then extrapolates by speed up to 1.2 s; bearing low-passed; ~10 fps in battery saver; a few frames a second when nothing moves | — | — |
| Compass rotation | Device heading turns the cone / the map | ✔ DeviceOrientation (`webkitCompassHeading` or absolute alpha + screen angle), rAF-throttled; iOS permission asked inside the 📍 tap; compass-follow rotates the map at home; GPS heading above 1.2 m/s wins in nav | — | — |
| Pinch / rotate / tilt gestures | Pinch, two-finger rotate, two-finger drag tilt | ✔ MapLibre `touchZoomRotate.enableRotation()`, `dragRotate`, `pitchWithRotate`, max pitch 70; any gesture ends follow and shows Re-centre | — | — |
| Battery saver | "Battery saver" in nav settings | ✔ auto under 20 % and not charging, or on / off: no 3D, no animations, 1× pixels, ~10 fps camera | Modules honour `body.saver` (no blur, no animation) and `REDUCED` | — |
| Large text / reduced motion / a11y | Larger text in nav | ✔ `body.big`, `prefers-reduced-motion` (no sweep, instant sheet), ARIA labels, 44 px targets | AI panel `role="dialog"`, messages `aria-live="polite"`, input focused on open only after a tap on touch devices | — |

## 4. What stays out, and why

| Google / Apple feature | Why it stays out | What SHARI NAV does instead |
|---|---|---|
| Live traffic and traffic-based ETA | No free, licensed source; a fake colour layer would mislead drivers | Faster-route check against our own engine every minute |
| Street View / Look Around / Live View AR | Google / Apple imagery, no free equivalent | Long-press pin + own reverse geocode; junction arrows |
| Place details (hours, photos, reviews, phone) for every place | Google Places / Yelp licences; Overpass excluded (usage policy, load on a volunteer server) | Curated KB for temples and crossings; SHG facts from the office via `nav-ai.php?facts=1` |
| Incident / hazard reports (Waze-style) | Needs accounts, moderation, a server | None |
| Toll prices | No open toll tariff data for India / Nepal plazas | "Has tolls" badge, Avoid tolls, "+ tolls" on the cost line |
| Transit directions | No GTFS for the India–Nepal corridor | S Hari corridor line + timetable (SHGROUTE) |
| Offline routing | Graph on the VPS | Offline tiles + voice; a route needs signal once |
| CarPlay / Android Auto / lock-screen widgets / background guidance | No such API for a web page | Wake lock keeps the screen on; PWA install |
| Continuous live-location sharing for riders | Needs a channel + consent | Static share links; buses on `track.php` |
| Indoor maps, EV charging | No data | None |
| Open-Meteo weather | Non-commercial licence | MET Norway via `nav-weather.php` (nv4); the AI's weather answers use the same endpoint, with its own ne / hi weather words (the core's `wxWord` is English only) |
| Google Places / Maps JS / Directions API | Paid; against the "own or free services" rule | Own index, own Valhalla, Nominatim only as a last fallback (1 request / s) |
| Automatic refunds / cancellations / date changes from the chat | The office settles these by hand (standing rule) | The `cancel` intent answers "office ले हातैले गर्छ" with Call / WhatsApp office actions and never reaches the server (P15) |
